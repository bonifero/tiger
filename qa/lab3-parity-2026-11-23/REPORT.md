# Сравнение оригинала и ремейка лабораторной №3

Дата: 23.11.2026. Область: весь студенческий сценарий лабораторной №3, соответствие методичке и удобство выполнения. Интерфейс преподавателя и управление общим каталогом отложены пользователем и в этой работе не менялись.

## Вывод и найденные пропуски

Все учебные действия оригинала сохранены: условие → кандидаты → отдельная проверка максимумов и x* → следующие грузы → ручное восстановление y/x → проверка результата и статистика. Найденные функциональные и пользовательские пропуски исправлены:

1. Неудачные подтверждения исходных данных раньше терялись при создании `Lesson`. Теперь они учитываются в итоговой статистике. Новая сессия сбрасывает счётчик; изменение масштаба — нет. Ошибки служебных операций сохранения/изменения размерности не считаются попытками решения.
2. В оригинале условие и принятые вычисления доступны на одном экране. В ремейке для них требовались отдельные окна. Теперь рядом с вводом расположена справочная панель: F текущего груза и предыдущие принятые максимумы; принятые кандидаты при выборе максимума; все принятые максимумы при восстановлении. Непроверенные ответы и готовое решение не раскрываются.
3. На финальном экране прежняя кнопка показывала только максимумы. Теперь можно открыть каждую принятую таблицу, включая кандидатов, и скопировать её.
4. Окно шириной минимум 1100 пикселей не помещалось на экран 1024×768. Теперь минимальный размер 980×620; проверено 1024×700. Типовой пример при 100% помещается рядом со справкой; при увеличении масштаба и больших задачах доступна прокрутка.
5. Масштабирование сбрасывало положение таблицы/выделение. Теперь сохраняются введённые значения, выделение, отметки ошибок и видимость выбранной ячейки.
6. Ошибки исходных F/весов/лимитов сообщались без точной позиции. Теперь сообщение содержит груз/поле, ошибочная ячейка подсвечивается и открывается в области просмотра.
7. Полностью невозможные количества справа (`x > floor(B/a)`) больше не занимают место в таблице кандидатов. Полная модель и проверка остаются прежними. Добавлено копирование справочных ячеек и таблиц.

## Сопоставление шагов

| Шаг методички / оригинала | Ремейк | Проверка |
|---|---|---|
| Ввести N, сформировать условие | Встроенный вариант/JSON либо «Новая таблица», отдельные лимиты количеств | Проверки редактора и импорта; N не смешивается с лимитом x |
| Ввести B, a, F; «Принять данные» | «Начать практикум» фиксирует условие | Неверный ввод отклоняется, отмечается и учитывается |
| «Шаг 1» для последнего груза | Сразу открывается этап N после принятия условия | Ненужное отдельное подтверждение убрано; вычисления не автоматизированы |
| Вручную заполнить допустимые кандидаты | Ручная таблица с блокировкой недопустимых клеток | Эталон проверяется независимым полным перебором |
| «Таблица заполнена» | «Проверить таблицу» | Неверная попытка сохраняет ввод и не продвигает этап |
| Заполнить f(y) и x*; «Заполнено» | Отдельная ручная таблица максимумов | Принятые кандидаты видны рядом, равные максимумы допустимы |
| Повторить N…1 | Те же этапы; у груза 1 только y=0 | Пример и все 5 вариантов, все промежуточные состояния |
| Показать принятые вычисления перед обратным ходом | Справка с максимумами и история всех таблиц | История содержит только принятые значения |
| Вручную восстановить y и x; «Готово» | Обе строки вводятся пользователем | Проверяется согласованность y/x, ограничение ресурса и оптимальность |
| Ценность и число ошибок | Ценность, расход/остаток, состав, ошибки и подсказки | Счётчики сохраняются до результата; TXT содержит протокол |
| Подготовить отчёт и ответить на вопросы | Экспорт расчётов для собственного отчёта | Не выдаётся за автоматически готовую работу для сдачи |

## Соответствие документам и осознанные отличия

Проверены `REQUIREMENTS.md`, методичка `source/Лаб_3/Лаб_3_методические указания_5 вариантов.doc`, README и предыдущая матрица требований в `qa/lab3-2026-11-23/REPORT.md`.

- Формулы и обозначения доступны сразу; пояснения к решению — по кнопке «Подсказка». Ошибка ответа не раскрывает правильное решение. Справка использует исходное условие и уже принятые ответы.
- Ошибки и подсказки учитываются отдельно, количество не ограничено; после 25 ошибок решение можно исправить и завершить.
- Оригинал связывает лимит количества с N. Ремейк имеет независимые лимиты: это позволяет корректно решить вариант 4 (пять бочек, ценность 2500). Это расширение, а не потеря функции.
- Оригинал проверяет первый сохранённый максимум; методичка разрешает любой равный. Ремейк принимает все равные оптимумы и согласованные итоговые планы.
- B=1 и точные дроби разрешены дополнительно к целочисленным исходным задачам.
- Варианты 3 и 5 сохраняют явно описанные трактовки неоднозначностей методички: до двух пар каждого вида; нормированная вместимость 4 для книг. Эти оговорки не скрыты и не устранены произвольно.
- Автоматическая сдача отчёта, ответы на контрольные вопросы, передача исходников преподавателю и оценка всей серии из 4 программ в эту проверку не входят.

Драйвер — собственный Python/Win32/PyAutoGUI, не результат REA native tools. Он проверяет хеш EXE, сопоставляет элементы с DFM, вводит значения обычными событиями, снимает окна и закрывает только созданный процесс. Предыдущие неуспешные отладочные прогоны были ошибками драйвера: ленивое создание Delphi-контролов, скрытое окно TApplication, задержка появления диалога и неподдерживаемый Ctrl+A в старом редакторе. Они не трактуются как дефекты вычислений исходной программы.

На английской системной локали runner часть старых ANSI-подписей отображается вопросительными знаками. Числа, таблицы и динамические итоговые надписи читаются; исходные русские подписи дополнительно известны из DFM. Русская локаль оригинала и все исключения старого EXE не считаются проверенными. Удобство сравнивалось по конкретным операциям и доступности данных, без утверждения о субъективной оценке всех пользователей.

## Отказы и исправление ответов в оригинале

[Windows run 45260227124](https://github.com/bonifero/tiger/actions/runs/45260227124) успешно завершил второй полный проход с четырьмя намеренными отклонениями:

1. Пустое исходное условие.
2. Неверный кандидат 999 вместо 0.
3. Равный максимум: при j=3, y=2 значения для x=0 и x=1 равны 19; оригинал отклоняет x=1, принимает x=0.
4. Несогласованное состояние y₂=1 вместо 0 при восстановлении.

После каждой коррекции работа продолжилась; итог — ценность 40, вес 4, план (0,1,1,2). Созданный процесс штатно закрыт, код 0, 141 действие. [Снимки и журнал](runtime-original-errors/), [лог](original-errors-windows.log).

Обнаружен дефект самого оригинала: после этих четырёх ошибок итоговая строка статистики отсутствует. Это видно на [финальном снимке](runtime-original-errors/12-result.png) и согласуется с ветвлением Button5Click по адресам 0x461d94–0x461df0: для 4 пропущено присваивание текста счётчика. Поэтому число 4 в scenario.json — ожидаемое число намеренных отказов, а не прочитанный с экрана счётчик. При одной ошибке предыдущий проход показывал счётчик явно. Ремейк выводит статистику при любом числе ошибок.

Для воспроизведения на Windows нужны Python3.12, Pillow12.x и pyautogui0.9.54. Запуск из репозитория: `python -X utf8 qa/lab3-parity-2026-11-23/original_runtime.py`; переменная `LAB3_ERROR_PROBES=1` включает все четыре отклонения, без неё выполняется основной проход с одной ошибкой исходных данных.

В последней сверке также добавлены постоянно видимые веса и B при восстановлении, компактные столбцы обратного хода и доступ к полному исходному условию из финальной истории без сброса сессии.
