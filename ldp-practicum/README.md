# ЛП · Практикум

Автономное Windows-приложение на Python/Tkinter для линейного и целочисленного программирования. Интерфейс использует оформление КТЗ-Практикума: тёмную боковую панель, светлую рабочую область, таблицы, вкладки и масштаб 50–150%.

## Запуск

Готовый EXE собирается в GitHub Actions: workflow **LDPTechs — tests / EXE** → **Run workflow** → после завершения скачайте артефакт **LDP-Practicum-windows-x64** и запустите `LDP-Practicum.exe`. Установка Python пользователю не требуется.

Из исходников: `python app.py` (Python 3.12 с Tkinter). Для вычислений нет внешних зависимостей. SciPy/NumPy используются только независимыми проверками, PyInstaller — сборкой.

## Работа

1. Выберите пример или откройте JSON/INI. При создании таблицы задайте размерности, коэффициенты, знаки и min/max.
2. Нажмите «Проверить модель», чтобы просмотреть сформированное условие.
3. Для целых переменных включите «Целочисленно · отсечения». Дополнительный флажок «F также целая» накладывает отдельное требование на значение цели. В непрерывном режиме он не применяется.
4. Во вкладке «Решение» используйте «Следующий шаг» или «Решить полностью». Можно остановить вычисления и запустить их заново. Редактор блокируется на время активного сеанса.
5. Просматривайте таблицу, исходную модель и журнал. Нижний список позволяет вернуться к одному из последних 300 снимков; журнал сохраняет названия всех событий текущего запуска.
6. Окончательный статус и проверенный план доступны во вкладке «Результат».

«Добавить ограничение» копирует текущее условие с новой строкой для ручной подзадачи. Автоматического дерева ветвей и границ и хранения дерева пока нет.

## Математика

Точный двухфазный симплекс с искусственными переменными; прямые и двойственные повороты; смешанно-целочисленные отсечения Гомори. При росте дробей включается резервный поиск ветвями и границами с точными LP-оценками; переключение видно в журнале. Рациональные строки целочисленной задачи приводятся к целой решётке до добавления slack. Числа — `fractions.Fraction`, без промежуточного float. Десятичный вид меняет отображение, а не вычисления.

Ввод: `12`, `1/3`, `2.5`, `2,5`, `-3 2/5`. Все переменные неотрицательные. В целочисленном режиме все исходные переменные целые. Имена, включая многомерные имена из INI, отображаются в модели.

В непрерывном LP строгие знаки отклоняются с объяснением. В целочисленном режиме они точно нормализуются по решётке коэффициентов, а не простым сдвигом произвольного RHS на 1.

Конечный optimal-план повторно проверяется по исходным ограничениям, неотрицательности, целочисленности и значению функции. Ошибочные результаты старого EXE не используются как эталон.

Встроены пример и шесть вариантов. Вариант 4 по буквальному условию несовместен; вариант 2 использует прибыль как цену минус указанную зарплату, а не выручку. V6 стоимость задана в млн руб.

## Форматы

JSON хранит условие, имена и флаги integer/integer_goal. INI использует восстановленную схему LDPTechs; доступны импорт и экспорт. При экспорте INI имена нормализуются в одномерные x1…xn; исходная многомерная структура индексов не экспортируется. Для её имён используйте JSON. INI ограничен 20×20 для совместимости, JSON — 100 переменными и 200 ограничениями.

Запись атомарная через соседний временный файл. Сохраняется условие, а не текущая таблица/сеанс. При ошибке чтения текущая задача не заменяется.

## Проверки и сборка

`python -m pip install -r requirements-test.txt`

`python -m unittest discover -v`

Проверяются все варианты, числовые регрессии старого решателя, статусы, JSON/INI roundtrip, 80 случайных ограниченных задач в LP/IP против независимого HiGHS (160 сравнений), шаг/остановка/повторный запуск и масштаб GUI.

Для локальной сборки установите `python -m pip install -r ../.github/requirements-build.txt`, затем выполните `python build.py`. Готовый EXE копируется в корень этого проекта. GitHub Actions использует то же приложение, собирая `LDP-Practicum.exe` без добавления бинарника в Git.

## Ограничения первой версии

- 2000 вычислительных шагов/отсечений, 256 бит для промежуточных точных чисел и до 500 резервных узлов ветвления; исчерпание общего бюджета не считается доказательством несовместности.
- При неограниченной LP-релаксации и отсутствии целого допустимого базисного плана возвращается «целочисленный статус не установлен»: неограниченность LP сама по себе не доказывает неограниченность IP.
- Долгая отдельная операция над большими дробями может задержать обработку отмены до ближайшего события.
- Нет редактора/визуального дерева B&B, возобновления сохранённого сеанса, отдельной приближённой арифметики, проверки ответов студента или произвольных нижних/верхних границ вне введённых ограничений.
- Интерфейс проверен программно; полная ручная визуальная приёмка и проверка на другом Windows-компьютере ещё нужны.

Исходный LDPTechs и первая программа не изменялись.
