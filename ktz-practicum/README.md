# КТЗ · Практикум

Учебное Windows-приложение для лабораторной №1: транспортная задача методом потенциалов, пошаговая проверка ответов, поддержка вырожденных планов.

## Запуск

Распакуйте весь ZIP из Artifacts в Actions: `KTZ-Practicum.exe` и папку `variants/` рядом с ним. Откройте exe. Python и интернет для автономного EXE не нужны. Исходники запускаются командой `python app.py` (Python 3.10+ с Tkinter).

## Работа с задачей

1. Выберите вариант из списка, загрузите JSON через «Загрузить вариант из файла» или создайте таблицу своей размерности.
2. Заполните тарифы, запасы и спрос. «Проверить баланс» проверяет данные без показа недостающего объёма и без предложения нужной стороны.
3. При необходимости самостоятельно выберите «Добавить строку» или «Добавить столбец» и заполните объём фиктивной вершины и тарифы добавленной строки. Неверно выбранная сторона не исправляется автоматически. Для изменения выбора заново загрузите вариант или создайте таблицу.
4. Приступите к решению. Выбирайте клетки таблицы и вводите ответы на текущем этапе.
5. Потенциалы u вводятся в отдельный столбец справа, v — в отдельную строку снизу рабочей таблицы. После принятия они остаются в этих ячейках до перехода к следующему плану.
6. На этапе «Дальнейшее действие» студент выбирает «Продолжить» либо «Завершить». Автоматического сообщения «план оптимален» нет.

Масштаб таблиц: кнопки −/+ с шагом 10%, ввод процентов (10–200%) или выбор готового значения. «По ширине» подбирает масштаб для открытой таблицы в этих пределах; очень широкие таблицы могут требовать прокрутки. Ctrl + колесо над таблицей меняет масштаб относительно курсора, Ctrl + 0 возвращает 100%. Обычное колесо прокручивает таблицу. Введённые значения и выбранные клетки сохраняются.

Подсказка текущего этапа появляется только по кнопке «Подсказка». Каждое нажатие увеличивает счётчик «Ошибки / подсказки»; при переходе к следующему этапу текст скрывается, при начале новой задачи счётчики сбрасываются. Ошибочный ответ не меняет план и показывает только ошибку; правильный ответ переводит к следующему этапу. Журнал содержит принятые действия.

## Файлы вариантов

В `variants/` находятся шесть JSON-файлов: пример из методички и варианты 1–5. При запуске программа загружает эту папку рядом с `app.py` или exe. Без неё можно создать таблицу или импортировать свои файлы.

- «Загрузить вариант из файла» — выбрать JSON из любой папки; вариант добавляется в конец списка и открывается в таблице. Совпадающим названиям добавляется суффикс.
- «Загрузить все варианты» — выбрать папку (по умолчанию `variants`). Все JSON проверяются до импорта; только при успехе список заменяется целиком. При ошибке указан файл и причина, прежние список и таблица сохраняются. Пустая папка также не очищает список.
- «Сохранить вариант в файл» — сохранить текущую, в том числе отредактированную таблицу в выбранную папку. Если расширение не указано, добавляется `.json`. Имя файла используется как название варианта. Массового сохранения нет.

Формат: `name` — необязательное название (без него используется имя файла), `costs` — матрица тарифов, `supply` — запасы, `demand` — спрос, `dummy_row` / `dummy_col` — признаки последней фиктивной строки / столбца. Принимаются неотрицательные целые до 10¹² и от 1 до 30 реальных строк и столбцов. Несбалансированные исходные варианты разрешены; перед решением пользователь самостоятельно выполняет балансировку. Файл хранит условие, а не текущий сеанс решения.

## Математика

Базис хранится отдельно от перевозок: `0*` обозначает нулевую базисную клетку. Поддерживаются переходы θ=0 и правило Бланда против зацикливания. Внутреннее соглашение: vⱼ−uᵢ=cᵢⱼ, δ=v−u−c. Общий сдвиг потенциалов принимается.

Контрольные оптимумы: пример — 1370, варианты 1/4 — 830, вариант 2 — 1620, вариант 3 — 1240. Вариант 3 загружается с тремя реальными строками. Пользователь самостоятельно добавляет фиктивную строку, вводит объём 30 и тарифы 100, 0, 0, 100 по условию; для этой модели контрольный оптимум — 1240. Тариф 100 — штраф из условия, а не абсолютный запрет. Вариант 5 перенесён из исправленного условия: строки — четыре ремонтные базы, столбцы — пять видов ремонта; тарифы транспонированы относительно таблицы методички.

## Проверка и сборка

- `python -m unittest discover -v` — математические проверки, 400 случайных задач против независимого min-cost-flow, все учебные экраны, ручная балансировка, ввод потенциалов, масштабирование и файлы вариантов.
- `python app.py --smoke-test` — создание интерфейса и начало сеанса.
- `python build.py` — PyInstaller-сборка `dist/KTZ-Practicum.exe` с папкой `dist/variants/` и копией `КТЗ-Практикум.exe` в корне проекта. Нужны Pillow и PyInstaller; локальные зависимости поддерживаются в `.build-deps`.

Модули: `transport.py` — математика, `lesson.py` — учебный сценарий, `app.py` — интерфейс, `presets.py` — загрузчик файлового каталога для тестов, `variant_files.py` — JSON-варианты. `test_oracle.py` — независимый тестовый решатель.

Полная визуальная приёмка нового интерфейса и проверка на компьютере заказчика остаются отдельным этапом. Локальная сборка не обновляет опубликованный GitHub-релиз автоматически.
