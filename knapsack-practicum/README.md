# Рюкзак · Практикум 03

Учебное настольное приложение для лабораторной №3: динамическое программирование, нелинейные таблицы ценностей и ручное восстановление оптимального плана. Python 3.12+ и Tkinter, без внешних зависимостей для работы.

## Запуск

Из папки `knapsack-practicum`:

```bash
python app.py
```

На Windows достаточно готового `Knapsack-Practicum.exe`: Python и интернет не нужны. EXE собирается в GitHub Actions: **«Загрузка рюкзака — tests / EXE» → Run workflow → Artifacts**. Сборка и проверка EXE также выполняются в PR. Архив содержит README, JSON-варианты и документацию разбора оригинала. Встроенные задачи доступны даже без папки `variants`.

## Работа

1. Выберите пример или вариант 1–5 в списке — он применяется сразу после выбора. При несохранённых изменениях программа попросит подтвердить замену. Можно также открыть JSON либо создать свою таблицу кнопкой рядом со списком. Введите вместимость, веса, названия и полные ценности `F_j(x)` для каждого количества. Это не обязательно линейная цена: например, два предмета могут стоить больше или меньше удвоенной цены одного.
2. Нажмите **«Начать практикум»**. Условие фиксируется на время решения.
3. На каждом этапе вручную заполните допустимые клетки таблицы кандидатов. Затем отдельно укажите максимумы `f_j(y)` и выбранные количества `x*_j(y)`. Порядок грузов обратный: N…1. Недопустимые клетки отмечены тире; у первого груза только строка y=0.
4. Справочная панель рядом с вводом показывает исходные ценности, принятые кандидаты и максимумы. Во вкладке «История» доступны принятые этапы. Ошибка сохраняет введённые ответы и не продвигает решение; исправьте отмеченные поля. Одна неудачная отправка — одна ошибка, включая отклонённое подтверждение исходных данных. Подсказки учитываются отдельно.
5. Восстановите итоговые **y_j и x_j** от первого груза к последнему. y — ресурс, потраченный до текущего груза, поэтому y₁=0. Программа принимает любой допустимый оптимальный план, включая равные альтернативы.
6. После проверки доступны ценность, расход ресурса, состав рюкзака, статистика, просмотр всех принятых таблиц и экспорт текстового отчёта. Возврат к условию сохраняет этап, введённые ответы, принятые таблицы, ошибки и подсказки. Если ничего не менять, можно продолжить через «Решение» или кнопку «Продолжить практикум». Первое изменение условия сбрасывает решение и итог, отключая эти хлебные крошки; новое решение запускается кнопкой «Начать практикум».

Навигация «Условие › Решение › Итог» расположена в верхней панели; текущий этап выделен синим. Стрелки переводят ввод в соседнюю ячейку с сохранением значения, Tab — в следующую редактируемую.

На первой странице F(0) редактируется и вставляется вместе с остальными ценностями. Для вставки всей матрицы ценностей выберите первую F(0), для строк вместе с названиями и весами — первую ячейку «Название», затем нажмите Ctrl/Cmd+V. Ненулевое F(0) выделяется как ошибка при попытке начать практикум.

Таблицы прокручиваются по обеим осям. Масштаб 80–140% меняет таблицы; точные значения сохраняются. На небольшом экране включается компактная компоновка; проверено окно 1024×700. Масштабирование сохраняет выбранную ячейку и её видимость. Ctrl/Cmd+C копирует выбранную ячейку; в окнах справки можно скопировать всю таблицу. В числах допускаются `12`, `2.5`, `2,5`, `1/3`. Вместимость, веса и количества — целые. Полностью использовать вместимость необязательно.

## Файлы условий и подготовка отчёта

Чтобы подготовить отдельное условие, откройте JSON или выберите встроенный пример, измените ёмкость, веса и ценности, затем нажмите «Сохранить». Название отображается в блоке «О варианте»; новое имя варианта можно задать при сохранении JSON. Отмена диалога имени не меняет название и не записывает файл. Для другой размерности задайте число типов и общий лимит, нажмите «Новая таблица»; чтобы изменить общий лимит существующей таблицы, измените верхнее поле «Лимит x» и нажмите «Применить лимиты». Значение применяется ко всем грузам, сохраняя имеющиеся ценности в оставшемся диапазоне. Если верхнее поле не менялось, эта кнопка применяет индивидуальные лимиты из строк таблицы. При уменьшении лимита значения за новой границей удаляются. Новые ячейки ценностей необходимо заполнить. Сохранение под новым именем создаёт отдельный файл; для изменения существующего откройте его и сохраните по прежнему пути.

Ненужный JSON можно удалить через файловый менеджер. Это не удаляет встроенный пример из списка: список хранится в `presets.py`, а JSON открывается отдельной кнопкой. Отдельная страница преподавателя с добавлением, изменением и удалением записей каталога пока не реализована.

Экспорт TXT — протокол расчётов для подготовки собственного отчёта. По общим требованиям из `source/` студент отдельно оформляет титульный лист, тему, цель, постановку, математическую модель, решение и выводы в терминах своей задачи, а также готовится отвечать на контрольные вопросы. TXT не является автоматически готовым отчётом для сдачи.

## Модель и формат

Максимизируется `Σ F_j(x_j)` при `Σ a_j*x_j ≤ B`, `x_j ≥ 0` целых. Число доступных значений в каждой строке F задаёт индивидуальный предел количества. `F_j(0)=0`; остальные ценности неотрицательные. Вычисления используют `fractions.Fraction` без округления.

Ограничения редактора/модели: 1–12 типов, ёмкость 1–200, количество каждого типа 0–200, до 60000 ячеек таблиц динамического программирования. Веса положительные, до 10¹². Исходные числители и знаменатели ценностей — до 256 бит. Очень большие таблицы неудобны для ручного решения; предпочтительны учебные размерности.

JSON сохраняет условие, а не незавершённую сессию. Запись атомарная. Пример:

```json
{
  "version": 1,
  "name": "Два груза",
  "capacity": 4,
  "weights": [1, 2],
  "values": [["0", "5", "12"], ["0", "8", "15"]],
  "labels": ["Груз 1", "Груз 2"],
  "description": "Максимизируйте ценность при ограничении веса."
}
```

## Варианты методички

| Задача | Контрольная ценность |
|---|---:|
| Пример · инвестиции | 40 |
| 1 · контейнеры | 21 |
| 2 · строительство | 34 |
| 3 · обувь | 3400 |
| 4 · перевозка | 2500 |
| 5 · книги, нормированная модель | 320 |

В варианте 3 неоднозначное условие трактуется как не более двух пар **каждого** вида. В варианте 5 единицы в методичке не согласованы: используется явно обозначенная нормированная модель B=4. Примечания включены в описания задач и JSON.

## Проверки и сборка

```bash
python -m unittest discover -v
python app.py --smoke-test
python -m pip install -r ../.github/requirements-build.txt
python build.py
```

`build.py` запускается на Windows и создаёт `dist/Knapsack-Practicum.exe`, `dist/variants/`, `dist/README.md` и `dist/docs/`. GUI-тесты требуют рабочую графическую сессию Tk. Для проверки только вычислений/файлов без GUI: `python -m unittest test_solver test_lesson test_formats test_presets -v`.

Проверяются промежуточные таблицы разобранного примера, все варианты, сотни случайных задач против независимого полного перебора, альтернативные оптимумы, незаполненная ёмкость, ошибочные ответы и восстановление y/x, точные дроби, JSON-обмен и работа интерфейса.

Модули: `model.py` — условие и валидация; `solver.py` — таблицы Беллмана; `lesson.py` — учебный автомат; `formats.py` — JSON; `presets.py` — задачи; `app.py` — интерфейс; `controls.py` — оформление элементов управления. Исследование EXE с Evidence, адресами обработчиков, отличиями и неизвестными: [docs/REVERSE_ENGINEERING.md](docs/REVERSE_ENGINEERING.md).
