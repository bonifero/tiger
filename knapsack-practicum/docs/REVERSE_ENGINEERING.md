## Восстановленный интерфейс

DFM содержит одну `TForm1` с заголовком «Задача о загрузке рюкзака (задача о ранце)», пять `TStringGrid`, два поля `TEdit`, шесть кнопок и 12 подписей. Сначала доступны ввод N и кнопка «Принять»; остальные рабочие элементы скрыты.

| Обработчик | VA | Наблюдаемые подписи / назначение по инструкциям |
|---|---|---|
| `FormCreate` | `0x460288` | Начальная просьба ввести число грузов |
| `Button6Click` | `0x462004` | «Принять»: считывает N, создаёт таблицы весов и ценностей |
| `Button1Click` | `0x4602c4` | «Принять данные»: проверяет заполненность, считывает вместимость, веса, F(x), блокирует условие |
| `Button2Click` | `0x46064c` | «ШАГ1» / «Перейти к шагу …»: создаёт очередную таблицу кандидатов |
| `Button3Click` | `0x4609e4` | «Таблица заполнена»: вычисляет эталонные кандидаты и сравнивает введённые значения |
| `Button4Click` | `0x46137c` | «Заполнено»: проверяет f(y) и x*(y), уменьшает номер груза либо показывает восстановление |
| `Button5Click` | `0x461abc` | «Готово»: проверяет y и x для каждого груза, показывает ценность и число ошибок |

`Button5Click` в диапазоне `0x461b9d–0x461c26` строит y и x по сохранённым решениям. В `0x461c8e–0x461d28` считывает и сравнивает по N значений y и x. Runtime подтвердил строки по грузам и столбцы y/x в оригинале. Ремейк использует транспонированный вид (две строки) и требует ручного заполнения **и y_j, и x_j**.

## Математика и учебный сценарий

1. Ввести N, вместимость B, веса a_j и **полные** ценности F_j(x), включая F_j(0).
2. Обрабатывать грузы от N к 1. Состояние y — ресурс, потраченный до текущего груза.
3. Заполнить кандидаты `F_j(x) + f_{j+1}(y+a_j*x)` при `y+a_j*x ≤ B`; последний груз использует только F_j(x).
4. Отдельно заполнить максимум f_j(y) и выбранное x*_j(y).
5. Для первого груза нужна только строка y=0. Для остальных используются y=0…B.
6. Восстановить план от первого груза к последнему: `y_1=0`, `y_{j+1}=y_j+a_j*x_j`.
7. Завершить работу только после проверки; показать ценность, использование ресурса и число ошибок.

Вычисление `a*x+y` и добавление следующего f находятся в `Button3Click`, `0x460d38–0x460e20`; выбор максимума — `0x460e23–0x460e88`. Переменная шага по адресу `0x465c18` уменьшается после принятого ответа (`0x4614ed`). Ошибки увеличивают счётчик `0x465c40` один раз в ветке отказа (например, `0x46055b`, `0x4611b7`, `0x461512`).

## Отличия ремейка, принятые осознанно

- **Отдельные лимиты количеств.** В оригинале N используется и как число типов, и как верхняя граница x: размер строк F задаётся N+1 (`Button1Click`, `0x460446`), верхняя граница кандидатов выбирается как min(N, floor((B-y)/a)) (`Button3Click`, `0x460c2e–0x460cad`). В ремейке границу задаёт длина каждой строки F. Это позволяет взять пять бочек в варианте 4 с тремя типами грузов.
- **Любой равный оптимум.** Оригинальный поиск сохраняет первый максимум: при `>=` пропускает замену (`0x460e3b–0x460e40`). Проверка x* затем сравнивает его с одним сохранённым значением (`0x4614a2–0x4614b9`). Методичка прямо разрешает любой максимизирующий x; ремейк принимает все равные варианты и любой допустимый оптимальный итоговый план с согласованными y.
- **Точные рациональные числа.** Оригинальные обработчики переводят введённые строки в целые. Ремейк допускает также дроби и десятичную запятую; веса, ёмкость и количества остаются целыми.
- **Вместимость 1 разрешена.** Оригинальная ветка отклоняет B<2 (`0x4603a9–0x4603b2`). Для математической модели нет причины запрещать B=1.
- Пустой ответ не принимается как ноль; ошибочные значения подсвечиваются, прогресс и остальные ответы сохраняются.
- Добавлены встроенные задачи, JSON-обмен, история принятых таблиц, подсказки со своим счётчиком, масштаб и текстовый отчёт. Эти возможности — решения ремейка, а не утверждения об оригинале.
- Нет автоматического заполнения ответов студента. Невыполненные этапы и итоговый оптимум не раскрываются заранее.

## Варианты и контрольные результаты

Все результаты независимо проверены полным перебором допустимых целочисленных наборов, без использования рекурсии решателя.

| Задача | Максимум | Все оптимальные планы |
|---|---:|---|
| Пример: инвестиции | 40 | (0,1,1,2), (1,1,0,2), (1,1,1,1) |
| Вариант 1: контейнеры | 21 | (2,0,1), (2,2,0), (3,1,0) |
| Вариант 2: дома | 34 | (1,0,0,1) |
| Вариант 3: обувь | 3400 | (1,2), использовано 5 из 6 |
| Вариант 4: грузы | 2500 | (5,0,0) |
| Вариант 5: книги, нормированная модель | 320 | (2,0,1) |

Для варианта 3 явно принято «до двух пар каждого вида»: исходная фраза неоднозначна. Вариант 5 содержит несогласованные единицы (4000 листов в запасе, расходы 1/2/2 листа, ценность только для x=0…3); в интерфейсе явно указана нормированная модель B=4. Буквальная модель B=4000 при лимите x≤3 дала бы 1180 и план (3,3,3); она не выдаётся за модель встроенного варианта.


- Runtime дополнительно подтвердил отклонение равного максимума в оригинале: [run 45260227124](https://github.com/bonifero/tiger/actions/runs/45260227124). Найден дефект отображения статистики ровно при 4 ошибках: ветка `0x461d94–0x461df0` не задаёт текст подписи. В ремейке статистика отображается при любом числе ошибок.
